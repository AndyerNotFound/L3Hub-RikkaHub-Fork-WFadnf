L3Hub Fork 功能总览
================================================================

本仓库是 RikkaHub（https://github.com/rikkahub/rikkahub）的二次开发版，对外名称 L3Hub。
本文按功能域清点 L3Hub 相对上游新增或实质改造的能力，作为查阅入口与验收清单使用；
逐项改动的来龙去脉、失败记录与实现细节仍在 FORK.md（../FORK.md），两份文档分工不同。

目录
----------------------------------------------------------------

1. 品牌与共存
2. 界面框架
3. 布局与导航
4. 聊天页与会话呈现
5. 生成控制
6. 子代理
7. 工作区、终端与服务
8. 提供商、模型与计费
9. 数据、备份与同步
10. 构建、测试与发布
11. 与上游的边界

口径与依据
----------------------------------------------------------------

- 清点对象为当前工作树：versionName L.3.3.0.4、versionCode 358，数据库版本 38，
  相对 upstream/master 领先 669 个提交。
- “新增”指仓库内不存在于上游的代码；“上游改”指功能源自上游、L3Hub 做了实质改造。
  仅换配色、换样式路由的上游功能不计入。
- 结论来自对代码与提交历史的只读核查，未执行 Gradle 构建，也未做真机验证；
  涉及观感、手势与解码器的条目以真机表现为准。
- 入口写法统一为“设置 → …”或“聊天页 …”；“—”表示没有独立界面，随其他流程生效。


================================================================
1 品牌与共存
================================================================

1.1 双应用共存
----------------------------------------------------------------

- namespace: me.rerere.rikkahub —— 保留，数百个文件的 import 不必改动
- applicationId: com.rikkahub.l3hub.wfadnf —— 与上游不同，系统视为独立应用
- Debug 变体: com.rikkahub.l3hub.wfadnf.debug —— applicationIdSuffix 自带
- Canary: com.rikkahub.l3hub.wfadnf.canary —— 由 -PappIdSuffix=.canary 注入
- 桌面名: L3Hub / L3Hub Canary / L3Hub Nightly / L3Hub Preview
  —— 由 -PappLabel 注入

- 不同 applicationId 加独立签名，才能与原版并排安装；同一 applicationId 换签名
  会报 INSTALL_FAILED_UPDATE_INCOMPATIBLE。
- 数据目录随包名独立，原版数据只能经备份导出再导入，不能在运行时直接读取。

1.2 移除 Firebase 与自更新
----------------------------------------------------------------

- 去 Firebase
  移除 google-services、firebase-crashlytics 两个插件与 bom / analytics /
  crashlytics 依赖；AppModule 去掉两个单例，ChatVM 去掉埋点与构造参数。
  上游的 google-services.json 由 CI 注入，本地缺失会让构建直接失败，去掉后
  本地与 CI 都不再依赖该文件。
- 关闭更新检查
  BuildConfig.UPDATE_CHECK_ENABLED = false，聊天抽屉与通知设置里的更新入口
  随之隐藏；Play 渠道原本就不检查更新。
- 版本目录残留
  gradle/libs.versions.toml 仍保留 firebase 相关条目，但没有任何模块引用，
  不影响构建。

1.3 名称、图标与关于页
----------------------------------------------------------------

- 应用名改为 L3Hub；各密度 ic_launcher / _background / _foreground 整体反色，
  深底白兔改为浅底黑兔。ic_launcher_monochrome 保持原样，主题图标按 alpha 取形，
  反色会变透明。
- 关于页标题改为 L3Hub，注明基于 RikkaHub；GitHub 与 LICENSE 链接指向本仓库，
  另保留“上游项目”一项指向 rikkahub/rikkahub。

1.4 应用内语言
----------------------------------------------------------------

- 支持语言: en / zh-CN / zh-TW / ja / ko / ru / de / ar，与 res/values-* 一一对应
- 存储: SharedPreferences（app_language），attachBaseContext 需要同步读取，
  不能放 DataStore
- 生效: Application 与 RouteActivity 各包一层 configuration，选完 recreate()
- 备份: settings.json 另存 appLanguageTag；仅覆盖式恢复写回，合并恢复保留
  当前语言

1.5 应用锁
----------------------------------------------------------------

- 应用锁（入口: 设置 → 通用 → 应用锁）
  appLockEnabled 与 appLockTimeoutMinutes（离开指定分钟数后要求验证）。独立
  AppLockActivity 用 KeyguardManager 校验设备锁屏凭据，并提供“返回桌面”；
  不是单独维护一份应用密码。
- 超时（入口: 同上）
  分钟数存 Settings，随备份走。

================================================================
2 界面框架
================================================================

2.1 组件风格：原生与 Miuix
----------------------------------------------------------------

- 界面风格（入口: 设置 → 偏好设置 → 界面风格）
  UiStyle.NATIVE / MIUIX。选 Miuix 后整棵树包一层 MiuixTheme，卡片分组、开关、
  按钮、复选框、单选、分隔线等骨架组件换实现；未迁移的页面保持原样，属于
  分阶段迁移而非整套重做。
- 组件路由（入口: —）
  ui/style/StyledComponents.kt 用同名函数包住原生与 Miuix 两套实现，调用点只改
  import；共享视觉组件集中在 ui/style，终端包不放应用级组件。
- 配色来源（入口: 设置 → 偏好设置 → Miuix）
  THEME（把 L3Hub 的位置色逐项映射）/ GENERATED（从主色生成）/ DEFAULT
  （Miuix 自带蓝）。默认 THEME，避免暗色下生成出近乎全黑的面板。
- 配色风格（入口: 同上）
  九档：TONAL_SPOT / NEUTRAL / VIBRANT / EXPRESSIVE / RAINBOW / FRUIT_SALAD /
  MONOCHROME / FIDELITY / CONTENT，仅在自动生成下有效。
- 按压反馈（入口: 同上）
  NONE / SINK / TILT，经 CompositionLocal 下发。
- 滚动回弹（入口: 同上）
  关闭时把 LocalOverscrollFactory 压回 null，沿用系统滚动。
- 卡片圆角（入口: 同上）
  miuixCornerRadius，整数 dp，默认 16。
- 设置页嵌入（入口: 设置 → 偏好设置）
  仅在 Miuix 档插入独立的 Miuix 偏好分组，原生档不显示。

2.2 调色板
----------------------------------------------------------------

- 调色板总开关（入口: 设置 → 偏好设置 → 主题 → 调色板）
  Settings.palette 三个字段均可空：presetId == null 表示不启用、行为与上游一致；
  light / dark 分别表示该侧被逐个改过。
- 48 个颜色角色（入口: 调色板 → 自定义编辑）
  覆盖 ColorScheme 全部 48 项，按主色 / 辅色与第三色 / 表面与背景 / 错误与线条 /
  高级五组呈现，高级组默认折叠。每个字段可空表示“没动过、跟着种子派生”，
  旧的九色配置仍可读。
- 六套预设（入口: 调色板页顶部）
  默认紫、海洋蓝、森林绿、落日橙、玫瑰、单色灰；单色灰另给中性种子，其余预设
  的中性色跟随主色。
- 配色生成算法（入口: 调色板页编辑模式）
  MONO / ANALOGOUS / TRIAD / COMPLEMENT / VIVID / MUTED，按色相偏移、彩度倍率
  与中性彩度区分。
- 表面族接管（入口: 调色板 → 表面与背景）
  withSurfaceFamily() 取 surface 的 HCT 色相与彩度（上限 12），在 scheme 自带
  音调上按表面色深浅整体平移；只换色相不平移会让“表层色”在大量
  surfaceContainer* 上看不出变化。
- 位置色层（入口: —）
  UiSlots 按位置定色（页面底、卡片、列表项、正文、标题、描边），调色板与
  AMOLED 压黑都作用在这层。
- 取色器（入口: 调色板任一角色）
  HSV / RGB 双模式、色卡、色号输入、可选 A 通道；边输边生效，失焦只做规范化。
- 色号解析（入口: 同上）
  #RRGGBB / #AARRGGBB / #RGB，纯函数并有 JVM 单测。
- 从色号生成（入口: 调色板页顶部）
  PaletteColors.fromSeed() 当场展开深浅两套色卡，可只应用到一侧。
- 探针与点屏取色（入口: 调色板 → 探针）
  界面刷成着色地图，点屏幕上任意一处读色并当场修改；另有“一键填色”。
- 编辑预览（入口: 调色板页）
  一屏假界面、角色影响预览、种子预览，改一格立刻看到落点。
- 导出 / 导入（入口: 调色板页底部）
  外套既有 ExportData（version + type + data）；导入也接受裸 PaletteSetting，
  便于粘贴手写片段。
- 优先级（入口: —）
  dynamicColor（跟随系统取色）> 调色板 > themeId。动态取色开着时调色板整块
  不生效，页面顶部可关。

2.3 字体
----------------------------------------------------------------

- 字体回退链（入口: 设置 → 偏好设置 → 界面 → 自定义字体）
  chatCustomFontPaths 有序列表组成 FontFamily(*fonts)，缺字形顺延到下一款
  （如英文→中文→俄文）；可调优先级、单项删除。
- 兼容旧配置（入口: 同上）
  旧的单字体 chatCustomFontPath / chatCustomFontName 仍读取；坏字体只丢自己，
  不拖垮整条链。
- 全局应用（入口: 同上）
  fontApplyGlobal 打开后用自定义字体替换全局 typography；终端与默认字体档禁用。
- 字号缩放（入口: 设置 → 偏好设置 → 界面 → 字号）
  fontSizeRatio 滑块，带输入框与实时预览。

2.4 背景特效与玻璃
----------------------------------------------------------------

- 背景特效三档（入口: 设置 → 偏好设置 → 通用 → 背景特效）
  OFF / BLUR / GLASS。OFF 时一条 haze 都不挂，直接回实色，低端机不为美化付代价。
- 模糊浓度（入口: 同页）
  blurOpacity，默认 0.45。
- 玻璃透明度（入口: 同页）
  glassOpacity，默认 0.35，只在玻璃档显示。
- 统一特效链路（入口: —）
  Modifier.effectSurface 把两档收敛成一条：模糊档背景色置空、着色叠在模糊之后，
  玻璃档着色交给 GlassStyle.tint；气泡、思考链、输入框、顶栏胶囊、设置项、
  抽屉、右栏、BottomSheet 共用，浓度才随滑杆一致变化。
- 可读性下限（入口: —）
  glassOverlayAlpha(floor)：详情面板与右栏 0.5、抽屉 0.65、两张 BottomSheet
  0.88；下限之上仍跟滑杆线性变化。
- 多色网格背景（入口: 助手背景 / 聊天背景）
  四个光斑（蓝 / 青 / 紫品红 / 橙琥珀）加 31 秒色相慢时钟，来回摆动 ±10~18°；
  深色压明度与 alpha、浅色彩度封顶 0.6；光斑渐隐改用同色 alpha=0，边缘不发灰。
- AMOLED 纯黑（入口: 设置 → 主题）
  上游功能；L3Hub 让 AMOLED 压黑在 UiSlots 位置层的优先级高于调色板底色槽。

2.5 动态模糊与动效
----------------------------------------------------------------

- 动态模糊（入口: 设置 → 偏好设置 → 界面 → 动态模糊）
  MotionBlurSetting：开关、基准半径 6dp、时长 280ms、滚动行程 32dp、滚动模糊
  独立开关；经 LocalMotionBlur 全局下发。
- 作用范围（入口: —）
  列表滚动、卡片收放、消息入场、正文气泡伸缩共用一套参数，各处按相对强度缩放。
- 复合动画（入口: —）
  MotionExpandCollapse / MotionExpandCollapseHorizontal 统一收放时长与模糊；
  关闭动效时直接 snap()，模糊不会拖在动画后面。
- 按钮阴影（入口: 设置 → 偏好设置 → 界面）
  appButtonShadow，填充与描边按钮挂投影；Miuix 档仍关闭。
- 思考强度样式（入口: 设置 → 偏好设置 → 界面）
  useL3HubReasoningStyle，用自有的强度图标与圆形滑块替代上游样式。

2.6 版式、缩放与显示模式
----------------------------------------------------------------

- 全宽组件（入口: 设置 → 偏好设置 → 通用 → 全宽组件）
  气泡撑满、MaterialTheme.shapes 换 SquareShapes（五档全 0dp）、贴边组件去掉
  左右留白并改用 safeDrawing 横向 insets；统一入口是 LocalFullWidthComponents
  与 adaptiveShape / adaptiveCornerRadius / adaptiveHorizontalPadding，关着时
  每个分支退回改造前取值。
- 界面缩放（入口: 设置 → 偏好设置 → 界面 → 界面缩放）
  50%–200%，每档 5%。主题用缩放后的 LocalDensity 提供整棵树，dp 与 sp 一起变；
  嵌套主题带 applyUiScale=false，避免终端等界面乘两遍。
- 显示模式（入口: 设置 → 偏好设置 → 界面）
  竖屏 / 横屏 / 自动 / 跟随系统，映射到 requestedOrientation 即时生效。
  Android 16 起，targetSdk 36+ 在最小宽度 ≥ 600dp 的屏幕上会忽略固定方向；
  自动与跟随系统不受限。
- 横屏隐藏状态栏（入口: —）
  横屏时顶栏贴到屏幕顶边，回竖屏恢复；按窗口尺寸判定，onResume 补判。
- 刘海避让（入口: —）
  横屏把 displayCutout 的左右内侧收到 RouteActivity 外层统一让开，页面不再
  各自让一遍。

2.7 页面转场与底部抽屉
----------------------------------------------------------------

- 页面转场规格（入口: —）
  ui/navigation/NavTransitions.kt 一份给中列与设置右列共用：进场默认自下而上，
  被盖住的页面 ExitTransition.None；容器变换页（heroEntry 全部页面与媒体创作）
  从卡片展开、返回收回，进出都不位移；滑入页（会话、设置首页）从下方滑入、
  返回原路滑出；返回与预测性返回同参；曲线在转场开始时读取，改动画速度不必重
  建 spec。
- 返回排队（入口: —）
  NavContext 统一判定：同帧重复 pop 去重；进场中的返回进入 pendingPops，转场
  落定后逐层出栈；预测性 seek 正倒向下一层时立即出栈。navigate /
  clearAndNavigate 清空排队。
- 离场页输入拦截（入口: —）
  NavInputGuard 给目标状态不是 Visible 的 entry 盖一层指针守卫，在 Initial 阶段
  消费输入，避免看不见的页面继续响应点击。
- 底部抽屉统一退场（入口: —）
  AnimatedModalBottomSheet(visible, onDismissRequest) 把窗口存活与可见性拆开：
  visible=false 先 hide()，播完再拆窗口。全部 ModalBottomSheet 调用点统一替换，
  不再出现“打开有动画、关闭硬切”。
- 共享元素（入口: —）
  可配对页面走 heroEntry：进场从条目展开、返回收回条目，两个方向都配对容器变
  换；页内元素（heroAnimation）只在进场配对，返回时通过 LocalNavEntryPopped
  摘掉，避免“整页收回条目 + 元素飞回”两种过渡同时出现；模型卡片进入编辑页
  即走这一条。
- 退场后再执行（入口: —）
  rememberSheetDismiss() 与对话框的 LocalDialogDismiss 同一约定；没有 sheet
  包着时退化为直接执行。
- 动效档位（入口: 设置 → 偏好设置 → 界面）
  animationSpeed：SYSTEM / FAST / GENTLE 各给一套 MotionScheme 交给主题，
  material3 自带的抽屉收放、菜单、遮罩、拖拽吸附只读这一个口子。
- 关闭动效（入口: 同上）
  disableAnimations：motionScheme 换 snap，手写动画先读 LocalAnimationsEnabled，
  避免关掉后侧边栏还滑 300ms。

3 布局与导航
================================================================

3.1 侧边栏抽屉
----------------------------------------------------------------

- 抽屉手势（入口: 聊天页左侧）
  收起态可从左边缘起手，也可在内容任意位置向右拖动拉出；展开后左滑收起。
  拖动跟手，松手按位移过半或甩动速度（350dp/s）从手指停下的位置继续播完
  开/关动画；点外侧与返回键照旧收起。
- 绘制阶段平移（入口: —）
  抽屉位置只写进一个只被绘制阶段读取的 offset，每帧只更新 graphicsLayer，
  不重新测量、不触发重组；抽屉内容不订阅流式会话，只拿当前会话 id。
- 底部胶囊（入口: 抽屉底部）
  左侧大胶囊“新聊天”，右侧用户头像；头像点击进设置，并带一段从抽屉飞向
  设置页顶部头像的过渡。
- 个人资料移位（入口: 设置 → 通用 → 个人资料）
  顶部用户信息（头像 / 昵称 / 问候）移除，改到设置；设置首页顶部改为紧凑
  标题栏加居中大头像，正好承接飞行动画。
- 日期分组折叠（入口: 抽屉会话列表）
  日期标题可点折叠/展开，折叠后只隐藏会话，不吞掉下一个标题，也不留空白间隙；
  走 MotionExpandCollapse。
- 文件夹折叠与排序（入口: 抽屉顶部文件夹芯片）
  文件夹段可折叠；按段内最新会话时间排序，不再手工拖拽排序。
- 文件夹菜单（入口: 芯片长按）
  绑定工作区、重命名等操作；绑了工作区的芯片带一个小盒子标记。
- 入口排布（入口: 抽屉中部）
  去掉“图像生成”入口；助手、收藏、统计三个入口改为“AI 翻译”下面的三行。

3.2 横屏三栏
----------------------------------------------------------------

- 判定：宽 > 高且宽 ≥ 600dp 进入三栏；竖屏仍用原有弹层。
- 整体缩放：整块 UI 用 LocalDensity 缩到 0.75（LANDSCAPE_UI_SCALE），字号、
  行高、控件一起缩；insets 按密度换算，物理高度不变。
- 左列：默认 300dp、默认展开，顶栏菜单按钮做宽度动画收合；拖动范围 200–440dp。
- 中列：宽度固定为“窗口 / 0.75 × 0.4”，夹在 360–640dp；收起左栏时整体左移、
  宽度不变，腾出的空间全给右列。宽度用可空 Dp? 表达，竖屏传 null。
- 右列：标签页式看板，宽度吃剩余空间；非模态——不盖聊天区、点聊天区不收、
  不接管返回键。
- 列宽拖动：左/中、中/右之间各一个 ColumnResizeHandle（10dp 抓取区加一条短
  竖线）；拖动时宽度动画切 snap()，手柄不落后于手指。
- 右列看板：九项：会话详情、任务树、清单与引导、用量、附件与工具、
  工作区文件、终端、模型、后台任务；标签条用 SecondaryScrollableTabRow，末尾
  “+”新建标签、标签上的 × 关闭。
- 自动开标签：清单或引导出现、一轮里首次改文件、首次进终端时自动打开对应
  标签，但不抢当前看板；同一轮手动关掉后不再弹回。
- 内容复用：附件 / 工作区 / 搜索 / 扩展、任务树、后台命令、模型列表、会话详情、
  都抽成不带外壳的 composable，竖屏套 Sheet、横屏塞右列。

3.3 设置分区与多列
----------------------------------------------------------------

4.8 流式生成的重组范围
----------------------------------------------------------------

- 不做时间节流：会话状态按 token 全速到 UI，聊天页没有采样或降频。
- 缩小重组作用域：会话以 State<Conversation> 交给消息列表；聊天页只派生自己
  关心的字段（有无消息、文件夹、清单、上下文占用等）。token 变化只重组列表，
  输入框、顶栏、背景与抽屉不跟着走。
- 抽屉：不订阅流式会话，只拿当前会话 id；底部列表生成中不会按 token 重组。
- 顶栏与回调：顶栏只拿会话 id 与有无消息；旧消息的分享回调不再捕获整份会话；
  模型对象按节点缓存。
- 玻璃底：输入框的玻璃底取静息背景源，不在每个 token 到达时重新模糊聊天列表。
- 贴底跟随：生成中的贴底是程序滚动，不叠整屏滚动模糊；用户自己往回翻时照常
  保留。
- 动画收敛：弹性伸缩只保留高度动画，不按高度差挂 RenderEffect；头像旋转只给
  生成中的那一个头像，其余头像不挂无限动画；思考预览直接贴底，避免每个 token
  重启滚动动画。

5.1 WARN / MAX 门限与预设
----------------------------------------------------------------

模型上两个门限，分别表示“性能最佳点”与“性能骤降点”：

- WARN —— 超过后回复质量开始下滑
  用量条转提醒色；自动压缩可选以它为预警线。
- MAX —— 到达后禁止继续发送
  发送时 toast、ChatService.sendMessage、语音入队、队列派发四处硬拦截；
  Model.enforceMaxContext 关闭后只提示不拦截。

- 门限输入（入口: 模型编辑页 → 上下文门限）
  删掉上游“上下文长度”整段，只保留 WARN / MAX 两个预警门限。
- 预设（入口: 模型编辑页）
  ContextThresholdPresets 按模型名预填；contextThresholdsAuto 为真且两个门限
  都为空时才填，用户手改任一值后不再覆盖，页面提供“使用预设”恢复。
- 代际判定（入口: —）
  主版本号从模型名取（claude-3-5-sonnet 算 3 代、qwen2.5-72b 算 2 代），避免
  把旧型号误判成新代。
- 隐藏预警条（入口: 设置 → 偏好设置 → 界面）
  关闭后把 contextMeterStyle 置为 OFF，输入框上方的用量条整行隐藏。

5.2 自动压缩
----------------------------------------------------------------

- 入口：助手 → 记忆 → 自动压缩；开关、触发比例（autoCompressRatio，50%–95%，
  按 5% 取整）与预警线（autoCompressThreshold，WARN / MAX）。
- 配置粒度：每个助手一套，不放在全局偏好里。
- 触发点：Model.autoCompressTriggerTokens() = min(比例 × 上下文窗口, 选中预警线
  的门限)；预警线沿用模型里手填或预设的 WARN / MAX。
- 时机：回复结束后、派发收件箱之前检查一次；一轮中途每批工具执行完再检查一次。
- 判据：最近一次请求的 usage 达到触发点；检查点之前的 usage 不算数。
- 任务槽：压缩与生成共用会话任务槽 SessionActivity.Compressing：期间新消息
  照常排队、停止生成可取消、重新生成先取消它。
- 压缩范围：上一个检查点之后到末尾；自动压缩不留保留区，整段进摘要；手动
  压缩可另填保留条数。
- 摘要输入：上一个检查点加检查点之后的原文；检查点之前的原文不再重发。
- 写入：与手动压缩共用 insertCompressionCheckpoint，在原位置插入
  isContextCheckpoint 摘要消息。
- 状态：最后一条消息不再显示生成中；前台通知与 Live Update 显示“正在压缩……”。
- 上下文已满：到达 MAX 后确认发送会先弹窗；开了自动压缩则先放行，由压缩处理。
- 限制：provider 在流式输出中途才报超限时，这一轮直接失败，不整轮重跑、
  不重装这一步。

5.3 消息队列与强制插话
----------------------------------------------------------------

- 消息队列开关（入口: 设置 → 偏好设置 → 通用 → 消息队列）
  enableMessageQueue，默认开。关闭后一条用户消息都不进队列。
- 关闭后的行为（入口: 同上）
  生成中或等工具审批时打断当前回复、立即发送（待审批工具标成取消）；正在
  压缩上下文、或队列暂停还压着旧消息时拒绝并提示，输入框内容保留；语音模式
  改为一轮说完再开麦。
- 判定收敛（入口: —）
  判定集中在 service/MessageQueuePolicy.kt，发送、插话、语音共用。
- 强制插话（入口: 生成中输入框右侧按钮）
  仅队列开启时出现；MessageQueue.enqueueFirst 加取消当前 job，生成结束立刻
  派发队首。

5.4 引导提示词
----------------------------------------------------------------

生成过程中追加一句指令，插进正在跑的工具间隙，模型下一步就读到它，不必掐断
再重发。

- 实现：不新增协议、不改 agent 循环：引导被包成一条合成工具调用（tool_use +
  tool_result）写进当前助手消息，随消息落库与导出。
- 工具名：guidance，不注册进工具表，模型调不到；声明了反而会诱导它去调用。
- id：g_<16 位十六进制>，不带连字符（OpenAI 的 tool_call_id 上限 40 字符，整套
  uuid 会到 45）；每次插入用新 id，避免同一条消息里出现两个相同 tool_use 被
  Anthropic 整条拒掉。
- 请求组装：expandInjectedTools 把它拆成一条 user 消息，和通知的
  expandNotices 同一层，位置在工具结果之后；模型在历史里看不到这个工具。
- 插入顺序：通知 → 任务清单 → 引导，模型最后读到的是用户新给的指令。
- 第一步：本轮第一步只放通知，不插引导与清单，避免回答开头凭空出现一条工具
  调用。
- 去重：末尾已是合成调用时整批跳过；清单只在文本与上次注入不同时插，其余
  交给请求尾部的 TodoStateTransformer。
- 生效判断：清单按每一步的最新设置判断，中途关掉后下一个工具间隙就停，请求
  尾部与历史里已插的提醒也一起不再发。
- 模式：单轮 SINGLE 插一次即从收件箱删除；多轮 REPEAT 每批工具后都再插，
  直到取消。
- 存储：待发引导放 ConversationInbox.guidances，不落库；插入后成为消息的一部分，
  随消息持久化。
- 预设：设置 → 扩展功能 → 快捷消息 → 引导提示词，存 Settings.guideMessages，
  与快捷消息分开。
- 单测：GuidanceInjectionTest、GuidanceInboxTest、AgentLoopTest 的 current
  取值用例。

5.5 计划模式与执行权限
----------------------------------------------------------------

- 计划模式（入口: 助手 → 基础）
  Assistant.planMode 为真时不注册写文件、编辑、打补丁、测试工具，只留检索与
  只读 shell。
- 执行权限四档（入口: 助手 → 基础）
  READ_ONLY 只注册读类工具、shell 仅只读命令；READ_WRITE 写文件免审批、执行
  命令仍确认；APPROVAL 按工具默认值与工作区开关逐条确认（旧行为）；FULL
  全部放行。
- 工具覆写（入口: 设置 → 工具覆写）
  按来源分组（本地 / 记忆 / 搜索 / 会话 / 工作区 / 任务 / 技能 / MCP）列出
  工具定义快照；覆写内容单独存为 toolOverrides，不随应用或 MCP 自动更新，
  也不再随会话注册变化。

5.6 网络与重试
----------------------------------------------------------------

- 自定义重试（入口: 设置 → 偏好设置 → 网络）
  enableAutoRetry（沿用旧字段名，升级不丢状态）、retryMaxCount、
  retryIntervalSeconds、retryErrorCodes（逗号分隔的 HTTP 错误码，空表示只重试
  网络错误）。
- User-Agent（入口: 同上）
  networkSetting.userAgent。
- 全局代理（入口: 同上）
  proxyUrl / 用户名 / 密码。
- 按域名代理（入口: 提供商 → 高级设置）
  providerProxies（host → proxyUrl）与独立的用户名、密码映射，按接口域名
  分别走代理。
- 自签 CA（入口: 设置 → 偏好设置 → 网络）
  customCaCertificates，PEM 文本列表，追加信任自签 CA。

5.7 心跳
----------------------------------------------------------------

- 入口：助手 → 心跳。
- 行为：每隔一段时间让助手主动说一句；intervalMinutes 夹在 1–1440。
- 活跃时段：startHour / endHour，左闭右开，start > end 表示跨夜。
- 无模型：modelId 为空时只当闹钟，到点发系统通知，不调用模型。
- 有模型：在专属会话里把 prompt 发给它，回复留在历史里。

5.8 记忆
----------------------------------------------------------------

- 记忆只读（入口: 助手 → 记忆 → 允许修改记忆）
  enableMemoryWrite，默认开。关闭后对话里的助手只拿到读取工具，不能写、追加
  或替换片段。
- 助手独立 Dreaming 模型（入口: 助手 → 记忆）
  dreamingModelId，为 null 时跟随全局记忆模型；每个助手可以用不同模型整理
  记忆。是否在对话停下后自动整理仍由上游的“自动做梦”开关控制。

6 子代理
================================================================

三处开关配合，形成最小的多代理协作：

- 设为子代理（位置: 助手 → 基础）
  该助手才会出现在别的助手的派发列表里，表示“能被派发”，不附带派发工具。
- 派发子代理（位置: 助手 → 本地工具）
  助手拿到 dispatch_sub_agent 与 await_sub_agent 两个工具；子代理会话沿用
  同一开关与它自己的允许列表，可继续派发下一层。
- 允许派发的子代理（位置: 本地工具开关下方）
  多选目标；勾选后工具目录与 SubAgentRunner 只认这些助手，不勾选表示不限制；
  子代理继续派发下一层时用它自己那份限制。
- 任务树（位置: 聊天页右上角 / 横屏右栏）
  展开当前会话下所有子代理会话，以及每个会话里执行过的工具调用与输出。

- 工具参数：dispatch_sub_agent(assistant, task, wait, timeout_seconds)；
  await_sub_agent(conversation_id, timeout_seconds)。
- 会话模型：子代理跑在独立会话里，带 parentConversationId，挂在父会话下，
  不占主对话上下文；数据库新增 parent_conversation_id / sub_agent_task /
  sub_agent_state 三列。
- 层数：最多三代（主 → 子 → 孙），超过后工具直接返回提示；不能把任务派发给
  自己。
- 权限：子代理会话没有人在旁边点确认，工具调用一律按完全权限执行；ask_user
  没有真人可答，直接返回提示让子代理自行决定。
- wait=true：父回合停在这次工具调用里，等子代理跑完第一轮，结果直接作为工具
  结果返回；默认等 600 秒，可传 timeout_seconds（夹在 30–1800 之间）。超时或
  父回合被掐断，这一轮照样落盘并按后台通知补投。
- 立即失败：子代理没跑出结果（被停掉、生成出错、卡在工具审批、回复为空）时，
  wait=true 立刻拿到失败说明，不干等到超时。
- background（默认）：派发后立即返回；每一轮生成结束都把这一轮结果投回父会话，
  父会话正在生成时先缓冲，空闲后把多条结果合并成一条消息投递，不打断当前
  工作；回传正文带 finished round N。
- await_sub_agent：按顺序处理：会话被删就直说；还在跑就等下一轮（压着的旧轮次
  不算新结果）；已完成且有未投递结果就直接返回那一份并注明；已完成且没有
  未投递结果就说明“没有可等的了”；失败立即返回失败说明。取走的这一份当场
  取走，不再当通知投递。
- 回传账本：每个子代理一条账，等于“还在排队的结果数 − 欠账数”：正常跑完
  一轮加一；被 await 当场取走则加一后立刻减一；异常中止记一笔欠账；回传被
  父会话收下则清段。只有账大于零才回传；连续两轮正常结尾而前一轮未送出时
  合并成一条通知；老文件的待投递结果没有欠账列，按 0 处理。
- 队列暂停：父会话被停止或生成失败后队列暂停：队列为空时新结果自己恢复队列
  并开新一轮；还压着用户消息时继续等，免得通知混进不会执行的消息里。
- 中间层：中间层子代理会话没有页面打开时也继续跑：收到孙代理回传就直接开
  下一轮，否则整条链会断在中间层。
- 回投消息：角色存成 USER 以便各家 provider 带进请求，但带 isSubAgentNotice
  标记；聊天页按“子代理任务完成 · 系统自动回传”的卡片渲染，导出 XML 记作
  system，组装请求时补一句“不是你输入的内容”。
- 可见性：子代理会话就是普通会话：出现在侧边栏与历史里，也能被搜索；打开时
  侧边栏切到它自己的助手，parentConversationId 只用来画任务树。
- WebUI：GET /api/conversations/{id}/subagents 读直接子会话摘要，面板按树
  列出并可跳转；回投消息按标记画成系统卡片。

7 工作区、终端与服务
================================================================

7.1 检索工具与分段读取
----------------------------------------------------------------

- workspace_list
  列目录，走 backend 的 listFiles，本地 Rootfs 与 SSH 工作区共用同一套实现；
  条目上限 500，超出置 truncated。
- workspace_glob
  按通配符匹配文件名，默认 500 条、可传 max_files（上限 2000）；整棵跳过
  .git / node_modules / build / dist / target 等目录，层数上限 12、扫描条目
  上限 4000。
- workspace_grep
  逐文件内容匹配，默认 200 行、可传 limit（上限 1000）；单文件 512KB、最多
  扫 800 个文件、单行截到 400 字符，遍历与 glob 共用跳过规则。
- workspace_read_file
  新增 offset / limit（1-based 行号）与返回里的 startLine / endLine /
  totalLines / truncated；整文件读取仍受字节上限约束。
- repo_map
  带 max_files（上限 800）产出符号级文件地图。
- workspace_apply_patch
  走统一 diff。
- workspace_git / workspace_test
  计划模式下只注册只读形态。
- workspace_shell
  支持 background=true，stdout / stderr 合并写入日志文件；配套
  workspace_shell_output（按 offset 读增量）与 workspace_shell_kill。

7.2 只读命令免审批
----------------------------------------------------------------

- 判定位置：WorkspaceCommandPolicy，纯函数并有单测。
- 放行：只读命令：ls、cat、grep、rg、find、git status / diff / log 等。
- 仍要审批：命令替换、重定向、子 shell、后台运行、find -exec / -delete、
  git 写操作。
- 保守原则：命令按分号、换行、管道符、&& 逐段判定；解析不确定一律判为需
  审批，误判只多一次点击。
- 提示同步：系统提示里说明新工具与免审批范围。

7.3 路径安全
----------------------------------------------------------------

- 软链逃逸：写文件前按可写根做 canonical path 校验，软链把路径带出可写区即
  拒绝写入并说明原因。
- 路径语义：WorkspacePaths 按字面处理、不跟软链；宿主侧另用 canonical path
  拦截。
- 解析收敛：路径解析收敛为两套内核供工具复用，失败按拒绝处理，不放行。
- 补全索引：WorkspaceIgnoreMatcher 按目录逐级累积 .gitignore 并补默认忽略集，
  规则解析复用检索工具同一套 GitIgnoreMatcher，避免两处语义漂移。

7.4 文件夹绑定工作区
----------------------------------------------------------------

- 入口：抽屉文件夹芯片长按 → 绑定工作区（多选）。
- 语义：文件夹持有一组工作区，落在组里的会话统一使用；会话 config 里固定的
  工作区保持原样。
- 运行时解析：FolderRepository.workspaceBindingOf(conversation) 现取文件夹绑定，
  盖在 Settings.getAssistantOf(conversation) 上；换绑立即对全组生效，移出
  文件夹即恢复自己的绑定。
- 子代理：子代理会话自己没有分组，沿 parentConversationId 向上找父会话文件夹，
  最多 3 跳。
- 写回还原：聊天页拿到的助手带着“不是自己的”工作区，ChatService 写回前还原
  成会话自己的绑定，防止绑定被固化成快照。
- 界面：聊天页工作区入口在文件夹接管时只显示“由文件夹 X 提供”，不可改写；
  芯片带小盒子标记。
- 删除工作区：WorkspaceRepository.delete 调 FolderRepository.detachWorkspace，
  摘掉文件夹引用。
- 数据：conversation_folder 加 workspace_id / workspace_ids 两列，Room 35 → 36。
- Web API：FolderDto 增加两个字段，新增 POST /api/folders/{id}/workspaces
  （留空即解绑）。

7.5 SSH 工作区修复
----------------------------------------------------------------

- 远程目录不可读导致“测试连接”整体失败
  目录探测失败只作为 SshProbeResult.remoteDirIssue 返回（不存在 / 不是目录 /
  权限不足 / 其他），连接照样判成功；编辑页说明原因，并在成功后提供“主目录”
  按钮一键填回远程用户 home。
- 换机或换包名后凭据解不开
  导入时 SshCredentialSanitizer.dropUnreadable() 清掉解不开的字段；打开编辑页
  时 usableSavedSecrets() 再校验并回写，界面如实显示“未填写”，不再沿用坏密文
  去连服务器。
- 目录列表慢
  listFiles 不再对目标目录多 stat 一次；含软链的目录改成一条 exec 一次问出
  哪些子项是目录，服务器不允许 exec 或输出截断时退回逐个 stat。

7.6 内置 SSH 服务端
----------------------------------------------------------------

- 入口：设置 → Web 服务器 → 在终端中使用。
- 依赖：org.apache.sshd:sshd-core（版本走 libs.versions.toml 的 apache-sshd），
  SLF4J 走已有 slf4j-android。
- 认证：只开密码认证，密码复用 Web 服务器访问密码，不维护第二份令牌；用户名
  任意（示例 l3hub）。
- 绑定：默认 127.0.0.1；打开“允许局域网访问”才绑 0.0.0.0；端口默认 2222。
- 主机密钥：filesDir/ssh/hostkey.ser，首次由 sshd 生成后复用（RSA，避免
  Android 上没有 EdDSA）。
- 通道：不申请 PTY，按行读命令；shell 请求进交互循环，exec 请求跑一条即退出。
- 命令：help、conversations、models、send <id> <text>、tail <id>、whoami、
  exit；直接调 ChatService / ConversationRepository / SettingsStore，不绕 HTTP。
- 令牌为空：拒绝启动，通知被收掉，界面显示错误。
- 服务复用：与 Web 服务器共用一个前台服务 WebServerService 与同一条通知，
  两个开关互相独立。

7.7 终端
----------------------------------------------------------------

- 模块来源：:terminal 取自 termux-app 的 terminal-emulator（上游引入），包名
  保持 com.termux.terminal 以兼容 terminal-view aar；TerminalSession 改为经
  TerminalTransport 收发，本地 pty 走 LocalPtyTransport，原生部分为
  termux_pty.cpp。
- 终端页：扩展 → 工作区 → 工作区详情 → 终端；多标签、后台运行，会话由
  WorkspaceTerminalSessionManager 缓存复用。
- 横屏终端看板：右栏“终端”标签复用同一批会话，切回整页终端还能接上；顶部是
  工作区、页签、新建与关闭，面板窄所以不搬 160dp 标签条。
- 主题：终端固定深色，嵌套 RikkahubTheme(colorMode = DARK, applyUiScale =
  false)，不二次缩放。
- 键盘：看板用 imePadding() 上收，底部行不被盖住。

7.8 Web 服务器与 WebUI
----------------------------------------------------------------

- Web 服务器：上游 Ktor 嵌入式服务加 mDNS 广播；启动前检查端口占用并显示

- WebUI 上下文用量条：输入框上方按模型 WARN / MAX 画两条进度条，数据取最近

- WebUI 引导：GET / POST /api/conversations/{id}/guidance 走会话收件箱，支持

- WebUI 子代理：GET /api/conversations/{id}/subagents 按树列出直接子会话并可
  跳转；回投消息按系统卡片渲染。
- WebUI 文件夹绑定：文件夹菜单多选工作区、星标主工作区与解绑，走

- 类型检查：CI 增加 Web UI typecheck，每次 push 跑 pnpm run typecheck，后端
  DTO 与前端类型对不上在合入前就红。

7.9 后台运行
----------------------------------------------------------------

- 电池优化白名单（入口: 设置 → 偏好设置 → 通知）
  已加入白名单显示状态；未加入时点按拉起系统授权，没有弹窗的系统退回电池

- 子代理后台（入口: 助手 → 本地工具）
  默认后台执行、结果回投；需要结果时用 wait=true 在工具调用里阻塞等待，
  不空转、不轮询。

8 提供商、模型与计费
================================================================

8.1 多密钥与轮换
----------------------------------------------------------------

- 录入：apiKey 按空格、换行或逗号分隔多个 key，自动去重、去空。
- 轮换：KeyRoulette 两种：随机，或 LRU（持久化到 cacheDir/lru_key_roulette.json，
  按 providerId 分桶，单 key 记录最近使用时间，一天过期）。
- 停用：disabledApiKeys 记住停用的 key，不参与轮换。
- 标签：apiKeyLabels 给每个 key 起名，便于在界面上辨认。
- 失败转移：KeyFailoverProvider 每次请求从轮换的 key 开始，失败时自动换下一个；
  流式请求一旦已经吐过内容就不再重试，避免重复输出。聊天、标题、OCR 等请求
  共用。

8.2 提供商管理
----------------------------------------------------------------

- 分组（入口: 设置 → 提供商）
  providerGroups 有序分组名与 providerGroupAssignments（提供商 → 分组）映射；
  模型选择弹窗按分组折叠展示，长按调整顺序。
- 删除内置提供商（入口: 同上）
  deletedBuiltInProviderIds 记住删过的内置 id，读盘时不再自动补回；可从
  “添加提供商”里恢复（用默认配置重建，不保留原 key 与模型）。
- 按域名代理（入口: 提供商 → 高级设置）
  providerProxies / providerProxyUsernames / providerProxyPasswords，按接口
  域名分别走代理。
- 自签 CA（入口: 设置 → 偏好设置 → 网络）
  见 5.6。

8.3 模型配置
----------------------------------------------------------------

- 模型编辑页（入口: 提供商 → 模型卡片）
  独立页面与横屏三栏见 3.4；身份、计费、门限、覆写不放在提供商页里维护。
- 上下文门限（入口: 模型编辑页）
  WARN / MAX 与预设见 5.1。
- 类型（入口: 同上）
  支持多类型模型（聊天加 OCR）；ModelType.OCR 让同一个模型条目可被选作 OCR
  辅助模型。
- OCR 辅助模型（入口: 设置 → 模型 → OCR 辅助模型，或单个模型自己的 OCR 辅助
  模型）
  候选顺序：模型指定 → 全局 OCR → 快速模型；提供商必须是支持视觉或 OCR 接口
  的一方。
- 能力与模态（入口: 模型编辑页）
  图片、视频、音频、工具调用等能力标记，供模型选择器与转换器判断。
- 覆盖配置（入口: 同上）
  请求头、请求体、模型参数覆盖。

8.4 模型计费
----------------------------------------------------------------

- 价目：ModelPricing：输入、输出、缓存命中、缓存写入、缓存读取、每次请求
  固定费用；每项按 priceUnitTokens(binaryUnits) 个 token 计价，十进制口径为
  每 1M token，二进制口径为每 Mi token。
- 变价规则：PriceRule 三种条件：时间段（本机时区）、本次请求输入 token 数、
  自定义表达式；按顺序匹配，第一条启用且命中的规则整张替换价目表；规则
  优先级与启用状态在模型编辑页维护。
- 结算时机：请求开始那一刻的价目表；写进 usage_record 与消息统计。
- 中途改价：对话循环里改价目表后，下一步请求按新价目算：ChatRequestFactory
  每步按最新设置重新取价（Model.repriced），只换价格表，模型身份仍用轮次快照。
- 在途请求：按开始时的价目结算，不因中途改价重算；压缩、标题、翻译等即时取
  设置的后台请求按最新价目。
- 单位：二进制 / 十进制口径随显示设置切换。

8.5 余额与额度
----------------------------------------------------------------

- 余额精度（入口: 提供商设置 → 获取账户余额）
  最多 12 位小数，去掉末尾 0、至少保留 2 位；unlimited 这类非数字文本原样
  显示；多 key 求和保留各自小数位。
- 余额预警值（入口: 同上，开关打开时出现）
  接受 10、CNY 10、$10、10 USD、¥10 等写法；带单位只与同币种比较，不带单位
  比较第一笔（多币种以第一笔为主币种）；余额小于或等于预警值时，余额文字与
  图标转 error 色。
- 余额刷新间隔（入口: 提供商 → 高级设置）
  quotaRefreshSeconds，0 表示关闭；关闭后只在打开页面时查一次。
- 额度查询（入口: 提供商设置）
  QuotaQuery 支持自定义请求头与解析规则，复用 getQuota；WebUI 同一份。
- 展示（入口: 设置页与聊天页）
  设置页最多两行；聊天页环形用量条里余额与左侧用量各占一半宽度，过长时在
  自己格子里省略。

8.6 请求调度（ProviderGuard）
----------------------------------------------------------------

- RPM 限制：最近 60 秒请求数达到上限后直接拦截，提示还要等多久。
- TPM 限制：最近 60 秒 token 用量加本次请求输入估算超过上限后拦截；请求开始
  按估算占位，结束换成真实用量。
- 自定义时间段限额：多条，每条独立选择时长（分钟 / 小时 / 天 / 周 / 月）、
  计量（请求次数 / Token / 费用）与上限。
- 窗口算法：滚动：从当前时刻往前推，用量逐条释放；固定：从起算日期时刻对齐，
  每满一个周期整段归零；首条请求：设定后第一条请求起算，归零后由下一条请求
  重新起算。
- 自动锁定：多条计划；“仅一次”在指定日期时刻触发，“每天”或“每周指定一个
  或多个星期几”从开始日期起重复，可设截止日期；支持跨午夜；锁定期间所有
  请求直接拦截。
- 覆盖范围：校验在 UsageRecorder 包住每一次模型请求的位置，聊天、标题、翻译、
  记忆整理、OCR 等共用同一套计数。
- 序列化：ProviderSetting.guard，随提供商配置序列化、备份与分享；
  copy(apiKey = ...) 与 copyProvider(...) 都不会丢。
- 兼容：旧备份没有 mode / anchorDate / anchorTime / effectiveAt，反序列化后
  按滚动窗口处理，行为与升级前一致。
- 历史用量：从 usage_record 读回进程启动前的部分，进程内记在内存；长窗口
  重启后仍有效。

8.7 覆写请求命令
----------------------------------------------------------------

- 位置：提供商 → 高级设置 → 覆写请求命令。
- 形式：一条 cURL 模板，替换 OpenAI / Claude / Google 的聊天请求。
- 占位符：{{apiKey}}、{{baseUrl}}、{{model}}、{{stream}}、{{body}}、
  {{messages}}、{{tools}}。
- 范围：只对聊天请求生效；OCR、生图与余额查询仍走原请求构建。
- 响应：仍按原提供商协议解析。
- 解析：ai/.../RequestOverride.kt，纯 JVM 单测 CurlCommandTest。

8.8 OCR、视频与语音
----------------------------------------------------------------

- OCR 辅助模型（入口: 设置 → 模型 → OCR 辅助模型）
  把图片读成文字并固化到图片 metadata，请求里替换成文本；模型级与全局两级
  配置。
- 视频消息（入口: 聊天页“+” → 视频）
  对所有模型开放；encodeMedia 按文件头识别 MP4 / MOV / 3GP / WebM / Matroska /
  AVI / FLV / WMV，Google provider 不再一律标 video/mp4；内联视频上限 20MB。
- 视频识别（入口: 自动）
  主模型不是 Google 时，VideoRecognitionTransformer 找支持视频的 OCR 辅助模型
  把视频读成文字，用 <video_file_ocr> 替换请求里的视频，结果固化到 metadata。
- 识别失败（入口: 视频消息下方）
  错误原因写进请求让主模型转告用户，同时经 onInputError 弹错误卡片；失败结果
  会固化但下一轮重试，补好设置后不用重发视频。
- 静默场景（入口: —）
  错误回调只用于聊天轮次，压缩摘要、标题生成这类只读请求保持静默。
- DeepSeek 搜索（入口: 设置 → 搜索服务 → DeepSeek）
  search_web / scrape_web 走 POST /v1/tools/search 与 /v1/tools/fetch。
- DeepSeek OCR（入口: 模型列表中的 deepseek-ocr）
  走 POST /v1/tools/ocr（multipart，purpose=text_recognition），逐页文本拼成
  一条 assistant 消息；版面标记与坐标在进入上下文前去掉。
- DeepSeek ASR（入口: 设置 → 语音 → 添加 ASR 提供商 → DeepSeek）
  POST /v1/tools/asr，16 位 PCM WAV 分段上传（单段最多 120 秒、8MiB），返回
  文本按段拼接，中文段之间不加空格。
- DeepSeek TTS（入口: 设置 → 语音 → 添加 TTS 提供商 → DeepSeek）
  POST /v1/tools/tts，音色 stella / tide，输出 wav 或 24kHz PCM；沿用现有
  150 字分片管线。
- 与上游的差异（入口: —）
  上游 3.3.0 也带 DeepSeek 语音；L3Hub 保留自有实现（baseUrl 带不带 /v1 都能
  拼出端点、中文段拼接规则、TTS 格式与 Markdown 过滤），只移植上游“停止录音
  先等协程退出”与 flowOn(Dispatchers.IO) 两处。

8.9 动图与视频素材
----------------------------------------------------------------

- 动图裁剪保留动画（入口: 助手详情 / 背景 / 头像选图）
  裁剪确认返回 CropResult：第一帧图、归一化裁剪区域（NormalizedCrop）与源文件
  是否为动图；CroppedImage 按裁剪区域旋转、缩放、平移后绘制，GIF / WebP /
  动画 HEIF 的动画不被压掉。
- 视频头像与背景（入口: 助手详情 → 头像 / 背景）
  Avatar.Video 与 backgroundIsVideo：视频静音循环播放，编码支持取决于设备
  MediaCodec；小于 72dp 的头像只显示一帧封面，避免一个列表挂多个解码器；
  背景视频的不透明度直接设在 View 上，模糊用 RenderEffect（Android 12+）。
- 聊天选图（入口: 聊天页“+” → 图片）
  源文件是动图时跳过裁剪直接发原图，避免 GIF 被裁成静态图。
- 清理（入口: —）
  头像与背景按 URL 比较，换裁剪区域不会误删同一个文件；复制、删除、备份路径
  都覆盖 Avatar.Video。

9 数据、备份与同步
================================================================

9.1 分层备份格式 .l3b
----------------------------------------------------------------

- 格式开关（入口: 设置 → 数据备份 → 本地 → 备份格式）
  INCREMENTAL（默认，.l3b）或 FULL（旧整份 zip）。
- 容器
  文件头 L3HUBBND1，之后是若干记录：L3B1 + headerLen u32 + header JSON +
  payloadLen u64 + payload（一段旧格式 zip）。
- 层头
  kind（base / delta）、createdAt、水位 since、schemaVersion、deviceId、
  hasDatabase、设置指纹、本层附件与 deletedFiles；只描述本层，不描述整链
  累计状态。
- 追加
  纯字节追加，已有记录不重写；尾部半截记录（断电、上传中断）读取时丢弃，
  下次追加前按有效长度截断。
- 增量内容
  按会话 update_at 的水位切：整条会话与消息节点、搜索行、删除墓碑、记忆、
  工作区、附件登记、媒体创作、用量流水，以及这段时间变化或新增的附件；
  没有时间戳的小表（分组、收藏）整表带上。
- 远端形态
  WebDAV / S3 不能原地追加，一个备份集是 backup_x.l3b（带文件头）加
  backup_x.l3b.d001…（裸记录）；恢复时按序拼成一份完整包，删除时整套一起删。
- 重开链
  无可接链、链状态丢失、结构版本变化、hasDatabase 与链首不同、层数达到 10、
  链首超过 7 天、链首属别的设备；远端追加前还核对链首对象是否仍在。
- 水位
  取上一层创建时刻往前让 2 秒，导出期间正在写入的会话宁可下次多带一遍，
  也不漏掉。
- 幂等
  增量合并按主键补、对端较新整条替换，重复应用同一层不产生第二份数据。
- 设备身份
  存在应用私有目录的偏好里，只用于决定能否接着追加。
- 兼容
  旧 zip 的恢复路径未改，.l3b 只是在外面多包一层；协议 2 的构建之间仍按增量
  zip 互换，协议 3 起改走 .l3b，接收侧按文件头识别，旧构建收到未知方法会
  失败、调用方据此降级。

9.2 备份范围
----------------------------------------------------------------

- 包内容：settings.json、数据库快照，以及 upload/、images/、skills/、fonts/、
  media_creation/。
- 新增目录：images/（AI 生图输出）加入备份范围，否则换包名恢复后生成的图片
  找不回来；旧备份没有该目录，恢复时跳过。
- 不备份：workspaces/ 不参与：文件可能很大，换设备后 proot 路径会变，按需
  自行导出；drafts 与工作区同属运行时状态。
- 软链：一律跳过，不下探也不打包；软链可能指向目录之外或成环，跳过并记警告
  日志，不再让整份导出作废。
- 未完成文件：media_creation 下 .partial 结尾的文件不入包（下载完才改名）。
- 提醒：上游功能：开关、1 / 3 / 7 / 14 / 30 天间隔、上次备份时间；L3Hub 改为
  visible 注册以走展开动效。

9.3 恢复
----------------------------------------------------------------

- 恢复选项：内容分设置 / 聊天记录 / 文件，方式分合并 / 覆盖；默认合并、
  三项全选，覆盖模式额外给一次警示；选择随待安装目录存到下次启动。
- 合并：不替换库文件，DatabaseMerge 在启动早期用原生连接把备份库里缺的行补进
  现有库，整个合并一个事务、按主键去重；消息节点、FTS、附件登记、用量流水等
  按专门规则处理。
- 覆盖：整库换成备份的库。
- 待安装目录：恢复一律先落 pending（payload/、options.json、journal.json），
  全部安装前原子改名；失败进 failed-* 并回滚 originals/；中断的安装下次启动
  按 journal 续做。
- 安装时序：RikkaHubApp 在 Koin / Room / SettingsStore 之前先
  applyPendingRestore，再 PendingDelta.applyPending；运行中的进程换不掉数据库。
- 附件路径改写：settings.json 整段正则替换；数据库遍历所有非 FTS 文本列，
  每列取样最多 4 个前缀后 REPLACE() 批量改；兼容 file:// 与裸路径、
  /data/user/N 与 /data/data，前缀相同则不动，可重复执行。
- SSH 凭据：解不开的密文段丢弃并回写，界面据实显示“未填写”。
- 应用语言：只有覆盖模式把 appLanguageTag 写回 SharedPreferences，合并模式
  保留当前语言。
- .l3b 物化：取最后一条完整的链；base 层的库落到待安装目录，后续 delta 按序
  SyncDelta.apply 打进同一副本；对不上 user_version 直接失败，不留半份数据；
  设置取最后一个带设置的层，附件逐层覆盖。
- 纯增量包：没有 base 层的 .l3b 不进整份恢复，交 PendingDelta 在启动时直接
  合并进现有库。
- 校验取舍：手动与云端恢复做整库 integrity_check；IPC 同步传的归档跳过（字节
  已由 zip CRC 校验，1.2GB 整库扫一遍几十秒），坏库仍会在 Room 打开时报出来。
- 设置迁移：settings.json 先过 SettingsJsonMigrator，再解码并要求 init == true，
  否则整份恢复中止；迁移后的值连生成 ID 一起写回，重启与重试保持一致。

9.4 版本同步（跨构建 IPC）
----------------------------------------------------------------

- 入口：设置 → 数据备份 → 版本同步。
- provider：每个构建导出 <applicationId>.sync（exported=true），方法走
  ContentProvider.call，不塞 Binder 事务；中转文件经 openFile 只读取走。
- 信任：正式版 / Canary / Nightly 签名密钥不同，signature 级权限反而挡人，
  改为按 UID 反查包名，且同 UID 的包必须全在可信清单内；数据中心也在清单里。
- 清单：先换清单：会话只给 id 与 update_at，墓碑单独一段，文件只给相对路径
  与字节数；超过 400 个待补文件就请对端整份目录打过来。
- 水位：每端各记“上次成功同步到对方哪个时刻”，拉取用对方写入时间、推送用
  自己写入时间，取开始同步那一刻；存独立 SharedPreferences，不随设置导入导出。
- 删除墓碑：sync_tombstone(kind, target_id, deleted_at) 表达“对方删了什么”，
  保留 180 天；表不进 Room 实体，每次开库 IF NOT EXISTS 建，避免为它把数据库
  版本推到 39。
- 增量 SQL：DeltaSync.export/apply 在 :syncproto，app 与数据中心共用；导出
  整段包在一个事务里钉住写连接（ATTACH 被 SQLite 判成只读，池化会把后续
  建表派给另一条连接），DETACH 另开空事务回到同一连接。
- 协议 3：对端自报 ≥3 时用 exportBundle 取一层（base 或 delta），否则退回
  增量 zip；自报值为常量表达式，PROTOCOL_VERSION（增量）仍为 2。
- 不压缩：同设备中转的归档用 Deflater.NO_COMPRESSION；手动备份与 WebDAV / S3
  上传仍压缩（那里省的是网络流量）。
- 结构上报：新增 schema 方法，直接读运行中的 sqlite_master，报库版本、
  identity_hash、页大小、体积、主表行数与全部表 / 索引 / 触发器 / 视图 DDL，
  不依赖编译期导出的 schema 文件。
- 状态提示：对方未装、无响应、已有一份待重启恢复、库版本比本机新、本机有
  待重启恢复，各自一句文案并禁用按钮。

9.5 数据中心
----------------------------------------------------------------

- 形态：独立应用 com.l3hub.database.wfadnf（:datacenter 模块），单独的桌面
  图标，与 L3Hub 一并构建。
- 用途：在本机各构建（正式版 / Canary / Nightly / 改过包名的分支）之间搬运
  数据，不依赖备份文件，全部经 ContentProvider 走 IPC。
- 结构上报：每个构建报运行中的 sqlite_master；数据中心把结构与数据分开处理，
  结构由目标自报、数据按目标结构重建，于是跨版本、跨分支都能投递。
- 页面：构建、快照、数据库、同步四页。
- 构建发现：已知包名照旧列出（未装显示“未安装”）；未知包必须真答上 ping 且
  自报包名一致才收进列表；历史遗留的既非已知构建又无快照的记录在加载索引时
  清掉，有快照的保留。
- 快照仓库：files/hub/index.json、packages/<包名>/snapshots/<id>/{rikka_hub.db,
  schema.json}、packages/<包名>/mirror/<相对路径>；每包留最近 3 份，最近的
  “同步前备份”始终保留。
- 数据库浏览：运行中的库只走 schema，无内容；快照只读打开，可看结构（行数、
  列、索引触发器视图 DDL、前 40 行）、会话（最多 300 条，读消息节点里的正文
  与附件路径）、附件（managed_files 最多 500 条加镜像目录统计）；读取失败
  显示原因，不静默为空。
- 导出裸库：SAF 选位置，文件名 <label>_rikka_hub_<yyyyMMdd_HHmmss>.db；快照
  直接复制，运行中的库先落一份不带附件的快照再复制；不压缩、不打包。
- 跨结构换算：按目标建表语句重建空库，逐表按列名取交集抄数据；目标多出的列
  用自身 DEFAULT（无默认值且非空则整表跳过并报告），源多出的列丢弃并记录；
  message_fts 连 rowid 一起抄，message_fts_rowid 按抄完的索引重建；写回目标
  identity_hash 与 user_version。
- 合并 / 替换：合并先把目标现状拉一份作回滚点，再在副本上合（墓碑先落地、
  对端较新的会话整条替换、缺的补、分组收藏补缺、工作区与记忆按 updated_at
  取新、用量流水只补本地新会话名下）；替换整库换掉，附件以镜像为准并清掉
  目标多出来的；目标库七张计数表全为 0 时合并退化成整库投递。
- 增量拉取 / 投递：协议 3 起拉取第一次要 base 层，之后只取水位之后的层并套在
  上一份快照副本上（快照本身仍是整份库）；合并模式投递第一次整库并记时刻，
  之后按 pushWatermark 导一层增量以 .l3b 投给目标；结构不一致或替换模式仍走
  整库。
- 附件差异：按清单与“路径 + 字节数”差异分批补，单批最多 400 个文件；内容
  变了但大小恰好相同的会漏一次。
- 归档不压缩：同设备中转一律不压缩；1.2GB 的库压缩 level 6 约 70 秒，整份
  复制 0.7 秒。
- 出包：DB-v*.*.* tag 或手动触发，产物 L3Hub-DataCenter-DB-v*.apk，内含
  libsimple.so 供 simple 分词器注册；CI 核对 tag 与 versionName 一致。
- 边界：目标构建需先更新到含数据中心授权的版本；跨结构换算只做列级映射，
  字段含义与 JSON 内部结构变化不在自动换算范围内。

9.6 云端备份与素材存储
----------------------------------------------------------------

- WebDAV 增量备份（入口: 设置 → 数据备份 → WebDAV）
  incremental=true 时按链上传 .l3b（首层整份、其后裸记录）；列目录时把
  xxx.l3b 与其 .d001… 归成一个条目。
- S3 增量备份（入口: 设置 → 数据备份 → S3）
  同上，rikkahub_backups/ 前缀下按链累积对象；不用增量时仍是每次重打的
  整份 zip。
- 云端恢复（入口: WebDAV / S3）
  与本地恢复共用恢复选项与同一套待安装目录，不再只有整份覆盖一条路。
- 备份项选择（入口: WebDAV / S3 配置）
  数据库与文件两类勾选；上游功能，L3Hub 继续往下传。
- 素材上传后端（入口: 设置 → 媒体 → 素材存储）
  S3 或 WebDAV 二选一，RemoteFileStore 抽象为 RemoteObjectStorage，上传后取
  临时地址供只接受 URL 的接口使用；缓存键含后端类型，换后端不复用旧映射。

9.7 导入与导出
----------------------------------------------------------------

- Markdown 聊天导入（入口: 设置 → 数据备份 → 本地 → 从其他 APP 导入 → 从
  Markdown 导入）
  认 **User**: / User: / ## User 三类标记（含中文“用户 / 助手 / 系统”），代码块
  内不切分，# 标题作会话标题，Exported on … 行忽略。
- XML 聊天导入（入口: 同上 → 从 XML 导入）
  支持 <message role="user"> / <content> 与 <user> / <assistant> 两种写法，
  根节点下多个会话分别导入。
- DeepSeek ZIP 导入（入口: 同上 → 从 DeepSeek 导入）
  上游 3.3.0 功能，本仓库文件与上游一致。
- SillyTavern 角色卡（入口: 助手编辑 → 导入）
  上游功能，L3Hub 只改按钮来源与样式路由。
- 调色板导入导出（入口: 设置 → 主题 → 调色板）
  外套 ExportData，导入也接受裸 PaletteSetting；data 为空或字段缺失即失败
  并给原因。
- 日志导出（入口: 日志页）
  直接序列化界面用的 LogEntry，文件名 l3hub-logs-<时间戳>.json。

9.8 设置容错与数据库
----------------------------------------------------------------

- 宽松解码：提供商、媒体生成、TTS、ASR 这类多态列表整体解码失败时改为逐条
  解码，只丢认不出的那一条（例如别的分支写进来的 deepseek-account），不再让
  整份设置读不出来导致应用起不来。
- 不再 halt：判定为 SerializationException 才降级；连 JSON 数组都解析不出来时
  记错误并返回空列表；读盘失败退回默认设置继续启动，persisted 同步设为
  默认值，之后只写改过的字段，不拿默认值盖掉磁盘原数据。
- 合并语义：恢复的合并模式只合并用户维护的集合（提供商、助手、提示词、主题、
  服务商、MCP、工具覆写、世界书、快捷消息等），同 id 以当前为准、缺的模型
  补进来；单值偏好（主题模式、模型选择、界面与网络偏好、语言）不被备份改动。
- 字段守卫：新增 Settings 顶层字段必须同时进 SettingsFields.SETTINGS_FIELDS 与
  PreferencesStore 的键，否则 SettingsFieldsTest 失败；backup_format 已有键
  与样本值。
- 数据库版本：AppDatabase version 38；35→36 加文件夹工作区两列，36→37 加
  usage_record.cost，37→38 补齐上游的 message_node(conversation_id, node_index)
  索引与 workspaces.storage_mounts。
- 迁移策略：上游 32→33 的 schema 与 fork 同名但内容不同，不照搬，改为一次性
  Migration_37_38 补齐；每个手写迁移前后打 DatabaseMigrationTracker 标记，
  恢复阶段失败时能定位卡在哪一步。
- schema 文件：补 35.json，按实际结构修正 33.json / 34.json 的 identityHash
  与 createSql，让 Room 下次升版时能找到完整链条。

10 构建、测试与发布
================================================================

10.1 渠道
----------------------------------------------------------------

- 正式版
  tag: v3.3.0.2、v3.3.0
  变体: githubRelease
  包名: com.rikkahub.l3hub.wfadnf
  Release: 正式 Release，自动成为 latest
- Canary
  tag: Canary-Build
  变体: githubRelease + -PappIdSuffix=.canary
  包名: com.rikkahub.l3hub.wfadnf.canary
  Release: Pre-release，滚动覆盖同一 Release
- Nightly
  tag: Nightly-Build
  变体: githubDebug
  包名: com.rikkahub.l3hub.wfadnf.debug
  Release: Pre-release，每夜自动
- 旧预览
  tag: v3.3.0-preview.102
  变体: githubDebug
  包名: com.rikkahub.l3hub.wfadnf.debug
  Release: Pre-release，仅历史兼容

三个包名互相独立，正式版、Canary、Nightly 可同装在一台手机上，数据互不影响。

10.2 出包与产物
----------------------------------------------------------------

- 正式版产物：L3Hub-<tag>-arm64-v8a.apk，单包含全部功能，附 .sha256。
- 产物形态：每个通道只产出一个 APK，不再区分含不含 LiteRT 的两个版本。
- 测试通道：Canary / Nightly / 旧预览各出单包，功能与正式版一致。
- 轮询通道资产：滚动 tag 的 Release 每次删掉本次未产出的旧资产，下载列表
  不留上一版的包。
- 发布说明：按“上一个 tag..本 tag”的提交生成；正式版取区间时排除预发布 tag，
  预发布反过来不排除；ci: / test: / build: 开头或作用域为这三者的提交不进入
  说明；超过 60 条截断；Canary / Nightly 用说明末尾的
  <!-- canary:from=… head=… --> 记起点。

10.3 版本号与签名
----------------------------------------------------------------

- 版本号：versionCode 每次递增，versionName 形如 L.3.3.0.4，与 tag 对齐；三段
  tag 要求 L.<tag 去 v>.NNN，四段 tag 直接用 L.<tag 去 v>。
- 递增校验：versionCode 必须大于上一个正式版 tag，否则覆盖安装时系统会当成
  没更新；滚动通道的 tag 不带版本号，不核对前缀。
- 正式版密钥：走 repository secrets 四项：keystore base64、store 口令、alias、
  key 口令；流程还原到 $RUNNER_TEMP 并写入 local.properties。
- 指纹校验：Release 变体的签名证书 SHA-256 与 build-apk.yml 中写死的值比对，
  不符即失败，避免 secret 被换后一路绿灯发出去。
- 调试包密钥：Nightly 与旧预览用仓库里公开的 keystore/l3hub-debug.jks，无保密
  价值，流程跳过密钥还原。
- 密钥备份：release key 丢失后无法再发出能覆盖安装的更新，需单独备份。

10.4 CI
----------------------------------------------------------------

- ci.yml（触发: push 到任意分支）
  JVM 单测；Web UI typecheck job 跑 pnpm run typecheck。
- build-apk.yml（触发: v* / Canary-Build / Nightly-Build tag、Nightly schedule、
  手动）
  校验 tag 与版本号、装 web-ui、按渠道选变体与包名、出包、核对签名、建
  Release。
- build-datacenter.yml（触发: DB-v*.*.* tag 或手动）
  出数据中心 APK，核对 versionName，附 libsimple.so。
- NDK 缓存
  :terminal 与 :workspace 的 CMake 需要 NDK 28.2.13676358（约 700MB），两个
  工作流都缓存；不缓存时现下，曾出现下载包损坏导致整轮失败。

10.5 工程约束
----------------------------------------------------------------

- 本机不编译：Termux 上不跑 Gradle；验证走 CI 单测与云端 runner，本机只做
  静态检查与文档。
- Debug 按 release 编译：debug 变体 isDebuggable = false，包名与 debug 签名
  不变，仍可覆盖安装；安装时 ART 做 AOT，启动与滚动快于调试构建，体积由
  57MB 降到 42MB。
- R8：optimization { enable = true } 默认注释掉：R8 在这台机器上单步要 8 分钟，
  改一行再出包太慢；最终版或 CI 再开。
- 文件预算：tools/file-budget.txt 记录超过 800 行的文件上限，
  tools/check-file-budget.sh 在 CI 里只许降不许升；聊天页等大文件先拆再加。
- 国际化：tools/i18n（Bun）增删与翻译字符串；页面级 key 带页面前缀。
- 单元测试：导航、聊天发送判定、数字草稿、模型草稿、门限定位、命令策略、
  引导、设置字段等纯逻辑均有 JVM 用例。

11.1 未并入或有意保留的差异
----------------------------------------------------------------

- SSH 跳板机：上游把连接重构成 endpoint 加 ProxyJump 隧道，与 fork 的认证
  失败指纹、远程目录探测改动叠在同一段代码上；本仓库保持自有 SSH 实现，
  SshJumpHostTest 不引入。以后要跳板机，需要把两处修复移植到新的

- 自动压缩开关：上游在偏好设置里重新加了全局开关与触发比例，L3Hub 仍按助手

- 深链与 action：AndroidManifest.xml 仍是 rikkahub://，action 仍是
  me.rerere.rikkahub.action.*；两版共存时外部应用触发这些会弹选择器。要彻底

- 网关移植内容：只移植数据侧能力（用量条、额度、引导、子代理、文件夹绑定），
  不移植网关的配色、MD3 换肤、模型菜单折叠与流式篡改（如句末加“喵”）。

11.3 平台与实现限制
----------------------------------------------------------------

- 屏幕方向：Android 16 起，targetSdk 36+ 在最小宽度 ≥ 600dp 的屏幕上忽略固定
  竖屏 / 横屏；PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY 只恢复
  resizability，不恢复方向锁，API 37 起连这个属性也没有，所以没有加。
- Miuix 覆盖：只迁移骨架组件与已改造页面，未迁移的页面在 Miuix 档保持原生
  外观，属分阶段状态。
- 视频播放：AVC / HEVC / AV1 / VPX 能否播放取决于设备 MediaCodec，容器由
  ExoPlayer 负责；小尺寸头像只取一帧封面，避免列表挂多个解码器。
- 数据中心：目标构建需先更新到含授权 provider 的版本；附件按“路径 + 字节数”
  判断是否需要重传，内容变了但大小恰好相同的会漏一次；跨结构只做列级映射。
- 备份：workspaces/ 不参与备份；软链不打包；.l3b 的远端形态是多个对象，
  恢复时需要整套对象都在。
- 压缩与截断：自动压缩不留保留区，摘要请求按正常对话组装；provider 流式中途
  报超限时这一轮直接失败，不整轮重跑。
